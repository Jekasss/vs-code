# Резюме: интеграция ПОС с внешними информационными системами

Исходный документ: `ПОС. Интеграция с ВИС (2) (2).docx`.

Документ описывает способы обмена данными между Платформой обратной связи (ПОС) и внешними информационными системами (ВИС). Он охватывает передачу обращений, статусов, ответов, файлов, статистики, классификаторов и внешних справочников, а также требования к защите персональных данных.

## Основные сценарии интеграции

| Сценарий | Направление обмена | Результат |
|---|---|---|
| Обработка в ВИС | Обращение: ПОС → ВИС; статусы и ответ: ВИС → ПОС | Заявитель видит в ПОС ход обработки во внешней системе |
| Обработка в ПОС | Обращение: ВИС → ПОС; статусы и ответ: ПОС → ВИС | Обращение из внешней системы проходит обработку в ПОС |
| Витрина данных | Обезличенная статистика: ВИС → ПОС | Формирование сводной отчетности |
| Аналитика | Обезличенные данные: ПОС → ВИС | Использование статистики ПОС во внешней системе |
| Классификатор ПОС | Категории, подкатегории и факты: ПОС → ВИС | Синхронизация тематик |
| Справочники ВИС | Записи справочников: ВИС → ПОС | Заполнение настраиваемых полей в формах и АРМ ПОС |

## Способы взаимодействия

Документ предусматривает:

- обмен через СМЭВ;
- REST API для обмена обращениями, статусами, ответами и файлами;
- REST API для статистики, аналитики, классификатора и справочников;
- экспорт и импорт файлов-архивов через внешний носитель.

**Важно:** в документе прямо указано, что новые интеграции ВИС с ПОС через REST API для обработки обращений более не настраиваются. Для сценариев «обработка в ВИС» и «обработка в ПОС» следует использовать СМЭВ. Описанные REST-методы сохранены в документе как техническое описание, но не являются целевым способом нового подключения.

## Обработка обращений в ВИС

При этой схеме ПОС передает во внешнюю систему все данные обращения и приложенные файлы. ВИС должна:

- подтвердить получение каждого обращения;
- передавать текущий статус обработки и наименование организации, где находится обращение;
- возвращать в ПОС итоговый ответ и приложенные к нему файлы;
- учитывать список обращений, изъятых ПОС из обработки в ВИС.

ПОС может также передавать в ВИС оценки заявителей по завершенным обращениям.

## Обработка обращений в ПОС

ВИС создает в ПОС обращение, передает данные заявителя, текст, тематику и файлы. После этого обращение обрабатывается по правилам ПОС. ВИС по идентификатору обращения запрашивает:

- текущий статус;
- итоговый ответ;
- файлы, приложенные к ответу.

Для корректной маршрутизации ВИС должна использовать актуальные коды категорий, подкатегорий и фактов из Классификатора ПОС.

## Обмен через СМЭВ

Через СМЭВ поддерживаются оба основных маршрута:

- обращение поступает в ПОС, обрабатывается в ВИС, а в ПОС возвращаются статусы и ответ;
- обращение поступает в ВИС, обрабатывается в ПОС, а в ВИС возвращаются статусы и ответ.

Кроме того, СМЭВ может использоваться для передачи в ВИС обезличенных статистических и аналитических данных. Подключение выполняется через соответствующие виды сведений на технологическом портале СМЭВ.

## Статистика и аналитика

Для загрузки в витрину ПОС ВИС передает CSV-файл или ZIP-архив, содержащий ровно один CSV-файл. Передаваемые данные:

- не должны содержать персональные данные и текст обращения;
- не должны дублировать обращения, уже полученные из ПОС или переданные в ПОС на обработку;
- используются для сводной статистической отчетности.

Все поля CSV обязательны, а дата и время передаются в UTC. ПОС позволяет проверять статус загруженного файла и получать ошибки по файлу или отдельным записям. Конечные статусы: успешная обработка, ошибка обработки или частичная загрузка с ошибками.

ВИС также может получать из ПОС обезличенные статистические и аналитические данные через API или СМЭВ.

## Классификатор ПОС

Для синхронизации тематик ВИС может получать из ПОС:

- неудаленные категории;
- неудаленные подкатегории;
- неудаленные факты;
- дату обновления каждой записи.

Эти данные нужны для корректной классификации и маршрутизации обращений. ВИС следует периодически обновлять свою копию классификатора.

## Передача справочников ВИС в ПОС

Внешние справочники используются как источники значений для настраиваемых полей в электронных формах и АРМ ПОС. Передача выполняется файлами форматов XLS/XLSX, ODS, XML или JSON после включения интеграции в АРМ Администратора.

При приеме ПОС проверяет:

- формат файла, внешний ID и наименование справочника;
- идентификаторы и названия всех записей;
- наличие и статус справочника в ПОС;
- разрешение на получение данных из ВИС;
- корректность региона, адреса по ФИАС и координат.

Операция атомарна: справочник создается или обновляется только при успешной проверке всех строк. При любой ошибке изменения не применяются, а в ВИС возвращается перечень некорректных записей и причин.

При обновлении:

- новые ID добавляются;
- существующие ID обновляются;
- записи, отсутствующие в новой выгрузке, архивируются;
- уже использованные в обращениях или автоправилах архивные значения сохраняются и продолжают действовать для этих объектов.

## Аутентификация и технический обмен

Для REST API используются:

- уникальные учетные данные для каждой ВИС;
- OAuth 2.0 и токен доступа, передаваемый в заголовке `Authorization`;
- REST-запросы по HTTPS;
- `multipart/form-data` для загрузки файлов.

Настройки подключения и включение конкретных видов обмена выполняются администратором ПОС по запросу владельца ВИС.

## Защита персональных данных

При передаче персональных данных по открытым каналам требуется применение сертифицированных ФСБ России средств криптографической защиты информации класса КС3. Целевое решение предусматривает ГОСТ TLS и HTTPS/TLS.

ПОС входит в состав ФГИС ЕПГУ, имеет первый класс защищенности ГИС и второй уровень защищенности персональных данных. Оператор ВИС самостоятельно обеспечивает защиту персональных данных по требованиям Постановления Правительства РФ № 1119. Для государственных и муниципальных ВИС дополнительно действуюют требования приказа ФСТЭК России № 17.

## Практические выводы

Для планирования интеграции необходимо:

1. Определить, где будет обрабатываться обращение: в ПОС или в ВИС.
2. Для нового обмена обращениями выбрать соответствующий вид сведений СМЭВ.
3. Согласовать с Оператором ПОС настройки, учетные данные, роли и разрешенные виды обмена.
4. Обеспечить сопоставление идентификаторов, статусов, тематик и организаций.
5. Предусмотреть подтверждение доставки, повторный обмен, контроль статусов и ошибок.
6. Организовать регулярную синхронизацию Классификатора ПОС и внешних справочников.
7. Выполнить требования к защите персональных данных и криптографической защите каналов.

## Вывод

Интеграция ПОС с ВИС строится вокруг двух базовых маршрутов: обработка обращения в ВИС или в ПОС. В обоих случаях нужно обеспечить сквозную идентификацию обращений, передачу статусов, ответов и файлов, синхронизацию справочников и защиту персональных данных. Для новых подключений обмен обращениями должен проектироваться через СМЭВ; REST API остается актуальным для отдельных сервисов статистики, классификаторов и справочников.
