# Настройка маршрутов обработки внутренних документов

## История версий

| Дата | Описание |
| --- | --- |
| 2026-08-05 | Начальная версия по итогам встречи от 04.08.2026 |

## 1. Общая информация

### 1.1. Цель

Обеспечить корректную последовательную обработку внутренних документов в 1С по утверждённым маршрутам и назначать задачи исполнителям по ролям или по структуре организации.

### 1.2. Область применения

В объём работ входят восемь маршрутов внутренних документов, переданных заказчиком. Маршруты 2–8 представлены линейными схемами в PDF. Маршрут 1, относящийся к служебной записке, передан в текстовом формате.

Входящие документы и упомянутые на встрече 24 более сложных маршрута в текущий объём работ не входят.

## 2. Текущее состояние (as is)

1. В 1С уже созданы виды документов и правила их обработки.
2. Существующие маршруты работают некорректно.
3. Для вида документа «Отчёт по уплате членских взносов» участники согласования получают задачи одновременно вместо требуемой последовательной обработки.
4. В составе участников этого маршрута отсутствует начальник общего отдела.

## 3. Целевой процесс (to be)

### 3.1. Общие требования к маршрутам

1. Для каждого из восьми видов внутренних документов должно быть настроено правило обработки в соответствии с переданной схемой.
2. Этапы каждого линейного маршрута должны выполняться строго последовательно: задача следующему участнику создаётся только после завершения предыдущего этапа.
3. На каждом этапе должна создаваться задача только тому исполнителю, который определён схемой маршрута.
4. Исполнителей следует определять по ролям, а не по конкретным физическим лицам. Это должно исключать необходимость изменять маршрут при смене сотрудника.
5. Перед созданием новой роли необходимо проверить наличие подходящей роли в информационной базе. Если роли нет, её следует создать в тестовой базе и сообщить об этом заказчику.
6. Если исполнитель однозначно определяется как руководитель конкретного подразделения, следует использовать данные о структуре компании и руководителе подразделения вместо создания отдельной роли.
7. Настройку и проверку маршрутов необходимо сначала выполнить на копии информационной базы.
8. После проверки заказчиком и получения подтверждения настройки должны быть перенесены в рабочую базу. При переносе следует использовать уже существующие в рабочей базе роли, если они соответствуют назначению.

### 3.2. Маршрут для вида документа «Отчёт по уплате членских взносов»

1. После запуска обработки документа система должна последовательно создать задачи согласования:
   1. главному бухгалтеру;
   2. управляющему делами.
2. Задачи главному бухгалтеру и управляющему делами не должны создаваться одновременно.
3. После успешного завершения этапов согласования система должна создать задачу исполнения начальнику общего отдела.
4. Этап начальника общего отдела является исполнением, а не согласованием.
5. Исполнитель третьего этапа должен определяться как руководитель подразделения «Общий отдел». На момент встречи начальником общего отдела названа Витясян.

## 4. Требования к реализации

1. Приоритетным способом реализации является настройка типовых механизмов 1С:Документооборота.
2. Изменение конфигурации допускается только если нужный маршрут нельзя реализовать типовой настройкой. Необходимость такого изменения должна быть обоснована по результатам анализа.
3. Изменения одного маршрута не должны изменять правила обработки других видов документов.
4. Настройки должны быть переносимы из тестовой базы в рабочую.

## 5. Критерии приёмки

### 5.1. Общие

- Для каждого из восьми видов документов запускается нужное правило обработки.
- Состав, тип и порядок этапов соответствуют переданной схеме каждого маршрута.
- В линейном маршруте до завершения текущего этапа задача следующему участнику не создаётся.
- Задача назначается актуальному исполнителю роли или актуальному руководителю указанного подразделения, а не жёстко заданному физическому лицу.
- При замене исполнителя роли или руководителя подразделения маршрут не требует перенастройки.
- Все восемь маршрутов успешно проходят полный цикл в тестовой базе.
- После переноса в рабочую базу состав и порядок этапов не изменяются.

### 5.2. Отчёт по уплате членских взносов

- Первой создаётся задача согласования главному бухгалтеру.
- Задача управляющему делами создаётся только после положительного завершения согласования главным бухгалтером.
- Задача начальнику общего отдела создаётся только после положительного завершения согласования управляющим делами.
- Задача начальника общего отдела имеет тип «Исполнение», а не «Согласование».
- В ходе маршрута не возникают параллельные задачи для этих трёх участников.

## 6. Открытые вопросы

1. Необходимо сверить точные названия всех восьми видов документов, состав этапов, их типы и порядок с переданными схемами.
2. Необходимо проверить, существуют ли в тестовой и рабочей базах роли «Главный бухгалтер» и «Управляющий делами», и корректно ли заполнен их состав.
3. Необходимо проверить, заполнен ли актуальный руководитель в карточке подразделения «Общий отдел».
4. Для маршрутов 1–8 нужно определить поведение при отказе в согласовании, возврате на доработку, отмене и переадресации задачи.
5. Нужно определить сроки выполнения этапов и правила эскалации просроченных задач, если они требуются.

## 7. Источник

Требования составлены по транскрипции встречи «Запись 1С. Статус по задачам» от 04.08.2026. В транскрипции детально разобран один маршрут; параметры остальных маршрутов должны быть дополнены по переданным заказчиком схемам.
