# Новый справочник «Договоры»

## История версий

| Дата   | Описание                                                |

## 1. Общая информация

### 1.1. Цель

Создать в информационной базе новый справочник «Договоры» для централизованного хранения основных сведений о договорах, их сроке действия, виде, стадии обработки, сторонах, исполнителе, авторе и предмете договора.

Обеспечить хранение и работу с файлами, присоединёнными к карточке договора.

### 1.2. Область применения

Доработка включает:

1. создание объекта метаданных «Договоры»;
2. создание перечислений, необходимых для реквизитов справочника;
3. создание формы списка и формы элемента справочника;
4. подключение нового справочника к механизму присоединённых файлов;
5. доработку справочника «Присоединённые файлы» и связанных с ним типов данных в объёме, необходимом для хранения файлов договоров.

## 2. Предпосылки для выполнения работ

В текущей структуре метаданных отсутствует отдельный справочник с заданным составом реквизитов для хранения договоров. Необходимо создать новую сущность и включить её в типовой механизм работы с присоединёнными файлами.

## 3. Концепция реализации

Договор хранится как элемент нового справочника. В карточке договора заполняются основные сведения, стороны договора, исполнитель, автор и предмет.

Вид договора и стадия обработки заполняются из предопределённых перечней. К каждому договору можно присоединить один или несколько файлов. Файл должен быть однозначно связан с конкретным договором.

## 4. Целевой процесс (to be)

### 4.1. Создание договора

1. Пользователь открывает список «Договоры».
2. Пользователь создаёт новый элемент.
3. Система открывает карточку договора.
4. Пользователь заполняет реквизиты договора.
5. Пользователь записывает карточку.
6. Система сохраняет значения в элементе справочника.

### 4.2. Работа с присоединёнными файлами

1. Пользователь открывает карточку сохранённого договора.
2. Пользователь открывает команду или вкладку «Файлы».
3. Система показывает файлы, связанные только с текущим договором.
4. Пользователь добавляет новый файл или открывает существующий.
5. При добавлении файла система создаёт элемент справочника «Присоединённые файлы» и связывает его с текущим договором.
6. После повторного открытия карточки список присоединённых файлов сохраняется.

## 5. Требования к справочнику «Договоры»

### 5.1. Состав реквизитов

| -- | ---------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1  | Номер                         | `Строка(11)`                                                    | Заполняется стандартным механизмом нумерации справочника 1С                                                          |
| 2  | Дата                           | `Дата`                                                            | Хранит дату и время; при создании заполняется текущими датой и временем                                       |
| 3  | Номер договора        | `Строка(100)`                                                   | Номер по договору/первичному документу; обязательный; контроль уникальности не выполняется |
| 4  | Период действия с   | `Дата`                                                            | Состав даты: дата без времени                                                                                                                     |
| 5  | Период действия по | `Дата`                                                            | Состав даты: дата без времени                                                                                                                     |

| 7  | Стадия обработки    | `ПеречислениеСсылка.СтадияОбработки` | «Рамочный»; «Законченный»; обязательный                                                                                                |
| 8  | Организация             | `СправочникСсылка.Организации`             | Выбор из справочника организаций; обязательный                                                                                   |

### 5.2. Перечисления

#### 5.2.1. Вид договора

Создать перечисление `ВидДоговора` со значениями:

1. `ДоговорПожертвования` — представление «Договор пожертвования»;
2. `ДоговорЗайма` — представление «Договор займа»;
3. `ДоговорАренды` — представление «Договор аренды»;
4. `ДоговорСФизическимиЛицами` — представление «Договор с физическими лицами»;
5. `ДоговорПоручения` — представление «Договор поручения»;
6. `ГражданскоПравовойДоговор` — представление «Гражданско-правовой договор».

#### 5.2.2. Стадия обработки

Создать перечисление `СтадияОбработки` со значениями:

1. `Рамочный`;
2. `Законченный`.

Значение по умолчанию — первый элемент списка: «Рамочный».

### 5.3. Требования к датам

1. Реквизит «Дата» должен хранить дату и время. Реквизиты «Период действия с» и «Период действия по» должны хранить дату без времени.
2. Если обе границы периода заполнены, дата начала не должна быть позже даты окончания.
3. При нарушении порядка дат система не должна сохранять карточку и должна показать предупреждающее сообщение.
4. При создании договора реквизит «Дата» должен автоматически заполняться текущими датой и временем.
5. Допускается открытый период действия: может быть заполнена только одна из дат «Период действия с» или «Период действия по».

### 5.3.1. Обязательность и автозаполнение

1. Реквизиты «Номер договора», «Организация», «Контрагент», «Стадия обработки» и «Вид договора» обязательны для заполнения.
2. При попытке записи карточки с незаполненным обязательным реквизитом система не должна сохранять элемент и должна показать сообщение с указанием незаполненного поля.
3. Реквизит «Исполнитель» при создании договора должен по умолчанию заполняться сотрудником, который указан для текущего пользователя и имеет признак «Основной».
4. Реквизит «Автор» при создании договора должен автоматически заполняться текущим пользователем. Поле «Автор» должно быть недоступно для редактирования.
5. Реквизит «Номер» при создании договора должен автоматически заполняться стандартным механизмом нумерации справочника 1С.

### 5.4. Форма списка

1. В списке договоров должны быть доступны как колонки: «Номер», «Дата», «Номер договора», «Вид договора», «Стадия обработки», «Организация», «Контрагент» и «Исполнитель».
2. Типовые механизмы поиска, сортировки и отбора должны работать для колонок списка.
3. Из формы списка должны быть доступны типовые команды создания, копирования и пометки на удаление элемента.
4. Доступ к справочнику должен осуществляться из раздела «Документы» — группа «Обычное».

![Актуальный макет формы списка договоров](<../Картинки/Макет формы списка договоров актуальный.png>)

### 5.5. Форма элемента

1. На форме элемента должны быть размещены все реквизиты из п. 5.1.
2. Реквизиты «Организация», «Контрагент» и «Исполнитель» должны быть визуально объединены в группу «Стороны договора».
3. Реквизиты «Период действия с» и «Период действия по» должны быть размещены в одной группе и отображаться как период «с — по».
4. Для полей ссылочного типа должен быть доступен типовой выбор из соответствующих справочников.
5. Для полей-перечислений должен быть доступен выбор только из заданных значений.
6. На форме должна быть доступна кнопка «Файлы» в виде гиперссылки.

## 6. Требования к присоединённым файлам

1. Справочник «Договоры» должен быть включён в состав типа, используемого для хранения владельца присоединённого файла.
2. Если владелец хранится в реквизите справочника «Присоединённые файлы», тип этого реквизита должен быть расширен ссылкой на новый справочник. Если платформенный механизм использует определяемый тип, план видов характеристик или иной общий тип, расширить следует именно его.
3. Каждый файл должен быть связан с одним элементом справочника «Договоры».
4. Из карточки договора должны быть доступны типовые операции с файлами, поддерживаемые текущим механизмом: как минимум добавление, просмотр, редактирование, сохранение изменений, печать, отправка.
5. При открытии файлов из карточки договора система должна показывать только файлы этого договора.
6. При добавлении файла из карточки договора владелец файла должен заполняться текущим договором автоматически.
7. Доработка не должна изменять связи и содержимое ранее созданных присоединённых файлов других объектов.
8. Права на файлы договора не должны превышать права пользователя на сам договор.
9. Поведение файлов при пометке договора на удаление должно соответствовать типовому поведению других владельцев файлов в информационной базе и не должно приводить к неконтролируемой потере файлов.

## 7. Права доступа

1. Права на просмотр, создание, изменение, пометку на удаление и работу с файлами должны настраиваться стандартными механизмами прав информационной базы.
2. Отсутствие прав на договор должно исключать доступ к его присоединённым файлам.
3. Необходимо создать две роли:
   - `Чтение договоров (СВ)`;
   - `Добавление и изменение договоров (СВ)`.
4. Возможность создания и редактирования договоров должна быть доступна пользователям с полными правами или ролью `Добавление и изменение договоров (СВ)`.
5. Возможность просмотра договоров должна быть доступна пользователям с полными правами, ролью `Добавление и изменение договоров (СВ)` или ролью `Чтение договоров (СВ)`.
6. Роль `Чтение договоров (СВ)` не должна предоставлять возможность создания или редактирования договоров.

## 8. Критерии приёмки

### 8.1. Справочник «Договоры»

1. В информационной базе доступен новый справочник «Договоры».
2. Карточка содержит все 12 реквизитов из п. 5.1 с указанными типами.
3. Длина «Номера» равна 11 символам, длина «Номера договора» — 100 символам.
4. Для вида договора доступны ровно шесть заданных значений.
5. Для стадии обработки доступны только значения «Рамочный» и «Законченный».
6. В полях «Организация», «Контрагент», «Исполнитель» и «Автор» хранятся ссылки на элементы указанных справочников.
7. При заполненных обеих границах периода система не позволяет сохранить дату «с», которая позже даты «по».
8. Сохранённые значения корректно восстанавливаются после повторного открытия карточки.
9. Поиск, сортировка и отбор по колонкам списка работают без ошибок.
10. Карточка не сохраняется без заполнения реквизитов «Номер договора», «Организация», «Контрагент», «Стадия обработки» и «Вид договора».
11. При создании карточки «Исполнитель» заполнен основным сотрудником текущего пользователя.
12. При создании карточки «Автор» заполнен текущим пользователем и недоступен для редактирования.
13. При создании карточки «Номер» заполнен стандартным механизмом нумерации справочника 1С, а «Дата» — текущими датой и временем.
14. Система позволяет сохранить несколько договоров с одинаковым значением реквизита «Номер договора».
15. При создании карточки «Вид договора» заполнен первым элементом соответствующего списка, а «Стадия обработки» — значением «Рамочный».
16. Карточка сохраняется при заполнении только одной из границ периода действия.
17. В конфигурации созданы роли `Чтение договоров (СВ)` и `Добавление и изменение договоров (СВ)`.
18. Пользователь с полными правами или ролью `Добавление и изменение договоров (СВ)` может создавать и редактировать договоры.
19. Пользователь с полными правами, ролью `Добавление и изменение договоров (СВ)` или ролью `Чтение договоров (СВ)` может просматривать договоры.
20. Пользователь, обладающий только ролью `Чтение договоров (СВ)`, не может создавать или редактировать договоры.

### 8.2. Присоединённые файлы

1. К сохранённому договору можно присоединить не менее двух файлов.
2. Каждый добавленный файл связан с текущим договором и отображается после повторного открытия карточки.
3. Файлы одного договора не отображаются в карточке другого договора.
4. Пользователь с необходимыми правами может добавить, открыть, сохранить на диск и удалить файл договора.
5. Пользователь без прав на договор не может получить доступ к его файлам.
6. Ранее созданные присоединённые файлы других объектов открываются и сохраняют свои связи после доработки.

## 9. Влияние на смежные объекты

1. Доработка типа владельца присоединённых файлов не должна нарушать работу с другими типами владельцев.
2. Доработка не должна изменять данные справочников «Организации», «Контрагенты», «Сотрудники» и «Пользователи».
3. Выбор ссылочных значений должен учитывать действующие права и отборы соответствующих справочников.

## 10. Границы требований

1. Лист фиксирует состав нового справочника и его подключение к механизму присоединённых файлов.
2. Интеграция с другими документами, маршрутами, отчётами, печатными формами, обменами и внешними системами в текущий объём не входит.
3. Миграция ранее накопленных данных о договорах в текущий объём не входит. Будет согласована в рамках отдельной задачи.
